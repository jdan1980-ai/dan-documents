# AGENTS.md — память и инструкции для AI-агентов этого репозитория

Этот файл — «README для агентов». Любой AI-помощник (Claude Code и др.),
открывающий этот репозиторий, должен прочитать его первым. Здесь фиксируется
контекст проекта и вся «память» о том, что уже сделано и почему, чтобы не
пересказывать это заново в каждой новой сессии.

Правило простое: если что-то важное сделали, решили или узнали — допишите
это сюда, а не держите в голове или в переписке. Файл — общая память команды
"пользователь + агент".

## 1. О проекте

**«Мой день»** — планировщик дня на React + TypeScript + Vite + Tailwind CSS.
Строит расписание под:
- хронотип пользователя (жаворонок / голубь / сова),
- роль (студент, офисный/удалённый сотрудник, фрилансер, родитель,
  предприниматель, спортсмен),
- приоритеты на сегодня.

Ключевые файлы:
- `src/lib/schedule.ts` — движок построения расписания (скелет дня + рутины +
  обязательные блоки роли + распределение свободного времени под приоритеты
  с учётом кривой энергии хронотипа).
- `src/data/chronotypes.ts`, `src/data/roles.ts`, `src/data/needs.ts` —
  справочные данные.
- `src/components/Onboarding.tsx` — три вопроса при первом входе (ритм, роль,
  приоритеты, время подъёма/отбоя).
- `src/components/Timeline.tsx`, `src/components/AddTaskForm.tsx` — таймлайн
  дня с отметками выполнения и добавлением своих задач.
- `src/lib/storage.ts` — сохранение плана в `localStorage` (переживает
  перезагрузку страницы).

## 2. Окружение разработки

```bash
npm install       # установка зависимостей
npm run dev       # локальный dev-сервер (Vite)
npm run build     # tsc -b && vite build
npm run preview   # предпросмотр собранного билда
```

## 3. Тестирование и проверки

```bash
npm run lint      # oxlint (конфиг — .oxlintrc.json)
npx tsc -b        # проверка типов (входит в npm run build)
```

Автотестов на данный момент в проекте нет. Перед PR минимум — lint и
typecheck должны проходить чисто.

## 4. Стиль кода и конвенции

- TypeScript строгий, без `any` без необходимости.
- Компоненты — функциональные, стиль текущих файлов в `src/components`.
- Стилизация — Tailwind CSS (v4, подключён через `@tailwindcss/vite`).
- Данные и бизнес-логика (`schedule.ts` и т.п.) отделены от компонентов —
  новую логику планирования добавлять в `src/lib`, а не в JSX.
- Комментарии — только там, где не очевидно «почему», а не «что».

## 5. Границы и что не трогать без явного запроса

- Не менять `.claude/skills/**` — это набор навыков Claude Code, не часть
  приложения.
- Не заменять `localStorage` на бэкенд/БД без явного запроса — проект
  сознательно offline-first.

## 6. Правила для PR / коммитов

- Коммиты — на русском или английском, кратко и по делу, в текущем стиле
  истории репозитория.
- Перед PR: `npm run lint` и `npm run build` должны проходить.
- Ветки создаются от актуального `main`.

## 7. Журнал памяти (Memory Log)

Живой лог того, что сделано и почему. Новые записи добавлять **сверху**,
формат: `## YYYY-MM-DD — краткое название`.

Каждая запись — по возможности:
- **Что сделано** — суть изменения.
- **Почему** — какая была задача/проблема.
- **Решения и договорённости** — что выбрали и почему именно так (чтобы не
  переобсуждать в следующий раз).
- **Что осталось / TODO** — если есть незавершённое.
